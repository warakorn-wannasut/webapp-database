โปรเจคนี้คือระบบร้านเกมคาเฟ่ เขียนด้วย PHP Laravel และใช้ SQLite (ไฟล์ database/database.sqlite)

เมื่อฉันขอให้อธิบายโค้ด:
1. ตอบเป็นภาษาไทย ศัพท์เทคนิคใช้ภาษาอังกฤษได้
2. ผู้อ่านเขียนโค้ดได้ แต่ไม่คุ้นกับ Laravel ให้อธิบายด้วยว่าแต่ละส่วนของ Laravel (route, controller, model, migration, Blade view, middleware) ทำหน้าที่อะไร เมื่อเจอครั้งแรก
3. อ่านไฟล์จริงก่อนอธิบายทุกครั้ง ห้ามเดาจากชื่อไฟล์
4. อธิบายทีละไฟล์ แล้วทีละ method ในไฟล์นั้น ทุก method ให้บอก: ทำอะไร, รับอะไรเข้ามา, คืนหรือแสดงอะไร, ถูกเรียกจาก route ไหนหรือจากที่ไหน, แตะตารางไหนในฐานข้อมูล
5. เวลาอธิบาย Model ให้บอกชื่อตาราง ฟิลด์ที่ fillable และความสัมพันธ์ (hasMany, belongsTo ฯลฯ) ว่าเชื่อมกับ Model ไหน
6. ถ้าไม่แน่ใจว่าโค้ดส่วนไหนทำอะไร ให้บอกว่าไม่แน่ใจ ห้ามเดา
7. เขียนผลลัพธ์เป็นไฟล์ markdown ในโฟลเดอร์ docs/ ไม่ต้องตอบยาวในแชท

ฉันเข้าใจ MVC ในระดับพื้นฐาน แต่ไม่รู้ว่าตัวแปรและคำสั่งในโค้ดมาจากไหนและส่งต่อไปที่ไหน

8. ทุกตัวแปรที่ปรากฏในโค้ด ให้บอก 3 อย่าง: มาจากไหน (ใครประกาศหรือใครส่งมา), เก็บข้อมูลอะไร (ชนิดและตัวอย่างค่าจริง), ถูกส่งต่อไปที่ไหน
9. ถ้าคำสั่งหรือ method ไม่ได้เขียนไว้ในโปรเจคนี้ (เช่น Auth::user(), view(), redirect(), where(), save(), validate(), compact()) ให้บอกว่ามาจาก Laravel ส่วนไหน คลาสอะไร ทำอะไร และเขียนเทียบว่าถ้าไม่มี Laravel ต้องเขียนเองยังไงโดยย่อ
10. ถ้าค่าถูกส่งเข้ามาแบบอัตโนมัติ (เช่น $request ใน controller, Model ที่รับผ่าน route parameter, $errors และ old() ใน Blade) ให้อธิบายว่า Laravel ส่งให้ตอนไหนและทำไมถึงทำงานได้โดยไม่มีใครเรียก
11. เมื่อมีข้อมูลข้าม layer (route → controller → model → view) ให้เขียนเป็นเส้นทางสั้นๆ เช่น ฟอร์มกรอกชื่อเกม → POST /games → GameController@store → $request->name → Game::create() → ตาราง games
12. ศัพท์เฉพาะของ Laravel ให้อธิบายตอนเจอครั้งแรกในเอกสารแต่ละไฟล์ ห้ามสมมติว่าฉันรู้อยู่แล้ว
